# Can an empty SCL list be reused after the residual changes?

**Design fixed before measuring pruning margins.** Use all count-growth continuation queries in the first 16 archived development frames (7101–7116, balanced B100/K100/.5 dB). Reconstruct each previous and new channel input and match the recorded hashes. At each actual cache miss on a previously queried pattern, examine its most recent query if its CRC-valid list was empty. Existing byte-identical cache hits are already free. Record all actual continuation calls as the denominator for possible savings.

For a surviving polar prefix, its SC path metric differs from minus the log of a sum over suffix completions by a constant common to prefixes of the same length. Future bits are relaxed in that sum, including future frozen bits. A channel LLR change d multiplies every complete-word unnormalized weight by a factor between exp(-||d||1/2) and exp(+||d||1/2). The relative change in log odds for any two prefixes is therefore at most ||d||1. If at every previous list cut the worst retained metric beat the best discarded metric by more than ||d||1, induction preserves the survivor sets. Hence a previously empty CRC-valid list stays empty. Metric ordering inside a survivor set need not be preserved. A strict gap excludes a changed tie at the cut. Nonempty-list reuse would require additional ordering/metric work and is outside this check.

Check the prefix inequality on a small exhaustive binary channel and test the certificate against the normal polar decoder under finite perturbations. Measure the minimum actual cut gap on old empty queries, compare with their actual LLR changes, and verify any proposed empty output directly. Promote only if more than 5% of all actual continuation SCL calls could be skipped before overhead, on at least three of the 16 frames. This is a real-arithmetic opportunity test; a deployable shortcut would also need a conservative numerical guard and charged timing. A failure stops this uniform perturbation certificate, without excluding data-dependent pruning bounds or less conservative rules for prioritizing retries.

**Variance-aware bound, after the first gate.** The uniform L1 test certified zero of 414 eligible retries. Changing the number of remaining users scales many unchanged chips in the same direction. Before rerunning any saved channels, fix a second certificate separating the common scale a = old variance / new variance from the signed numerator change. At depth t, M=2^(N−t) future polar input assignments enter the exact SC prefix mass Z. For their normalized weights w, log(sum w_i^a) lies between min(0,(1−a)log M) and max(0,(1−a)log M). Thus the worst/best cut gap g becomes at least a*g − |1−a|(N−t)log 2 − ||L_new−a L_old||1. At a final leaf the entropy penalty vanishes. Use the larger lower bound for a=1 and the physical variance ratio at each cut. Keep the same frames, denominators, 5% gate and exact-empty verification. The finite check enumerates the prefix log masses directly. This a priori generalization targets temperature changes, with no fitted parameter.

## Result

The 16 archived frames contained 3,045 continuation queries, including 765 existing exact-cache hits and 2,280 actual SCL calls. Four frames contained all 414 eligible changed inputs with a previously empty list. Every eligible input changed variance. The median smallest old cut gap was 0.000312 in path-metric units; the median full L1 displacement was 22.84, and separating the change in variance reduced the median remaining L1 displacement to 15.21. Neither certificate skipped a single call. The second finite test verified 1,152 prefix-odds ranges for each bound; 61 certified toy survivor sets included 57 empty lists. Stop both uniform worst-case certificates on this schedule. The data give an opportunity count for these sufficient conditions, not a necessity theorem for other approximate or code-specific retry rules. [Replay driver](retry_stability.py)
